01

Blur on every tile

High

Every section and every gallery tile carries .scroll-reveal, which animates filter: blur(10px) over 1000ms with will-change: filter. On /galleries that's 91 tiles each forcing its own compositing layer and repainting a blur every frame. Blur is a paint operation — it can't be done on the GPU the way opacity and transform can, and Safari is the worst at it.

The proposal keeps the reveal but drops the blur, shortens it to ~400ms, and removes will-change. The motion still reads as "arriving" — it just stops costing a repaint per frame per tile.

02

Image fade

Medium

Separately, every image fades in over 600ms. Combined with a 1000ms reveal, a tile takes over a second and a half to fully arrive even when the file was already cached. Photos should feel like they're there, not like they're developing.

Proposed: 220ms ease-out. Same switch above controls it — the two run side by side here so you can see them arrive together.

Already shipped from the audit (no mockup needed)

  • Lightbox grows from the tapped tile. It scaled from its own centre before, so tapping a corner tile made the card appear from mid-screen.
  • The places curtain stopped relayouting on scroll. Its preview animated width for 620ms — a layout property — and the live row changes on every scroll step. It's a fixed box that scales now.
  • Hover zoom is desktop-only. On touch, a tap fires a synthetic hover that sticks, so tiles stayed zoomed after you'd tapped them.
  • Lightbox exit easing. It used ease-in … reverse, which reverses the curve as well — the declared easing said the opposite of what it did.

Not changed, deliberately

  • The hero's slow intro and the collection cards' 6s pan are ambient, not UI — long durations are correct there.
  • No transition: all anywhere, and no animated layout properties left once the curtain is fixed. That part of the codebase was already clean.
